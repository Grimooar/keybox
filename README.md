# Ключница

Менеджер паролей для себя и команды. Устроен по образцу Bitwarden, но без своего сервера: данные лежат в вашем Dropbox, а шифруются и расшифровываются только на устройстве.

- Работает на компьютере и телефоне, ставится как приложение (PWA).
- У каждого есть личный сейф. Есть коллекции для всей команды и коллекции с доступом только для выбранных людей.
- Генератор паролей, коды 2FA (TOTP), история паролей, импорт из Bitwarden, Chrome, Edge, Яндекс Браузера и Firefox.
- Офлайн можно смотреть пароли из последней синхронизации.

## Как это защищено

| Что | Как |
|---|---|
| Мастер-пароль | Нигде не хранится. Ключ из него получается через Argon2id (64 МБ, 3 прохода) |
| Записи | AES-256-GCM, у каждой коллекции свой ключ |
| Доступ к коллекции | Ключ коллекции запечатывается отдельно для каждого участника (X25519 + HKDF) |
| Состав команды и права | Файл `org.json` подписывает владелец или админ (Ed25519). Админов подтверждает подписью владелец |
| Записи в коллекциях | Каждый файл подписывает автор, причём только тот, у кого есть доступ к коллекции. Есть счётчик версий против отката |
| Удаление участника | Ключи всех его коллекций меняются, записи перешифровываются |
| Вступление | Новый участник и админ сверяют проверочные коды (защита от подмены) |
| Браузер | Строгий CSP, никакого HTML из данных, ссылки только http/https, буфер обмена очищается через 30 с, автоблокировка |

Dropbox видит только зашифрованные файлы и имена участников. Названия коллекций тоже зашифрованы.

Код прошёл независимый аудит безопасности, все найденные проблемы исправлены и покрыты тестами (`tests/core.test.mjs`, раздел «регрессия по аудиту»).

**Ограничения схемы без сервера (их нельзя исправить кодом):**
- **Удаляя человека из команды, обязательно закройте ему доступ к папке в самом Dropbox и смените важные пароли на сайтах.** Новые записи он не прочитает, но то, что видел раньше, мог запомнить. В истории версий Dropbox у него остаются старые копии файлов.
- Тот, у кого остался доступ к папке, может удалить файлы или вернуть их старые версии. Подделать или прочитать данные он не может. Откат приложение замечает на устройствах, которые уже видели более новую версию. На **новом** устройстве (или после очистки данных браузера) откат заметить нечем, поэтому снова: закрывайте доступ к папке. Восстановить файлы можно через историю версий Dropbox.
- Если кто-то удалит ваш файл `users/<id>.json`, личный сейф пропадёт вместе с ним (восстанавливается из удалённых файлов Dropbox). Периодически делайте экспорт.
- Файлы участников видны всей команде, и мастер-пароль можно перебирать офлайн. Поэтому приложение требует фразу примерно на 60+ бит: 4 и больше случайных слов.
- Кто может менять код сайта (доступ к репозиторию на GitHub), тот может украсть пароли. Не давайте никому права на запись в репозиторий.
- Все сайты на `<логин>.github.io` используют одно хранилище браузера. Если вы держите там другие проекты, лучше привязать Ключнице отдельный домен, например `pass.gearpoint.pro`, или завести для неё отдельный аккаунт GitHub.

## Запуск за 10 минут

### 1. Выложить на GitHub Pages

1. Создайте на GitHub репозиторий, например `keybox`, и загрузите туда эту папку.
2. В репозитории откройте Settings → Pages → Source: «Deploy from a branch», ветка `main`, папка `/ (root)`.
3. Через минуту приложение будет доступно по адресу `https://<логин>.github.io/keybox/`.

### 2. Создать приложение Dropbox (один раз на всю команду)

1. Откройте https://www.dropbox.com/developers/apps/create.
2. Выберите **Scoped access** → **Full Dropbox** и придумайте имя.
3. На вкладке **Permissions** включите `files.metadata.read`, `files.content.read`, `files.content.write` и нажмите Submit.
4. На вкладке **Settings** в **Redirect URIs** добавьте адрес приложения, например `https://<логин>.github.io/keybox/`.
5. Скопируйте **App key** в `js/config.js` (`DROPBOX_APP_KEY`). Если не хотите править код, приложение спросит ключ при первом запуске.
6. Пока приложение в статусе Development, им могут пользоваться до 50 человек. Для студии этого хватит.

### 3. Создать команду

1. Откройте приложение, подключите Dropbox и оставьте папку `/Ключница`.
2. Придумайте название команды, своё имя и мастер-пароль. Вы станете владельцем.

### 4. Позвать коллегу

1. В Dropbox поделитесь папкой `Ключница` с коллегой (у него должен быть свой Dropbox).
2. Коллега открывает приложение, подключает свой Dropbox, указывает путь к папке (обычно тот же `/Ключница`) и нажимает «Я новый участник».
3. Он видит два кода. **Код команды** сверяет с вашим: он есть в разделе «Команда». Свой код называет вам.
4. У вас в разделе «Команда» появится заявка. Нажмите «Проверить и принять», сверьте код и выберите, какие коллекции ему открыть.

## Разработка

```sh
node tests/core.test.mjs   # тесты ядра: шифрование, роли, подмены, откаты
node tests/serve.mjs       # http://localhost:8765/#demo - демо-режим без Dropbox, данные в памяти
```

Сборки нет, это чистый JS (ES-модули). Единственная внешняя библиотека — `vendor/argon2.umd.min.js` (hash-wasm 4.12.0, MIT). Она подключена с контролем целостности (SRI), хэш: `sha384-tP0Wy54CKmng7i9EoTlPySD0hBx6Octj0VS6MfwlnUu111MPa+JLm0CCbep6XJ1W`.

После изменения файлов приложения поднимите версию `CACHE` в `sw.js`, чтобы у пользователей обновился офлайн-кэш.
