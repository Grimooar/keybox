# Ключница

Менеджер паролей для себя и команды, устроенный по образцу Bitwarden. Пароли шифруются и расшифровываются только на устройстве. Маленький сервер на Cloudflare хранит зашифрованные данные и следит, кто что может делать.

- Работает на компьютере и телефоне, ставится как приложение (PWA).
- Коллеге достаточно ссылки-приглашения: он открывает её, придумывает мастер-пароль, админ принимает заявку. Никаких аккаунтов.
- У каждого есть личный сейф. Есть коллекции для всей команды и коллекции для выбранных людей.
- Роли: владелец, админы, участники. Удалённый человек теряет доступ сразу на всех устройствах.
- Генератор паролей, коды 2FA (TOTP), история паролей, импорт из Bitwarden, Chrome, Edge, Яндекс Браузера и Firefox.
- Без сети можно открыть сейф и смотреть пароли из последней синхронизации.

Приложение: https://grimooar.github.io/keybox/ · Сервер: `server/` (Cloudflare Workers + D1, бесплатный тариф).

## Как это защищено

| Что | Как |
|---|---|
| Мастер-пароль | Нигде не хранится. Из него на устройстве получается ключ (Argon2id, 64 МБ), а из ключа два независимых подключа: один шифрует ваши ключи, второй проверяет пароль на сервере |
| Вход | Сервер отдаёт ваши зашифрованные ключи только после проверки пароля. После 8 неудачных попыток вход блокируется на 15 минут. Так никто не может скачать файл и перебирать пароль у себя |
| Записи | AES-256-GCM, у каждой коллекции свой ключ. Ключ запечатан отдельно для каждого участника с доступом (X25519) |
| Состав команды и права | Файл команды подписывает владелец или админ (Ed25519). Админов подтверждает подписью владелец. Ключи владельца закреплены на устройствах участников |
| Запросы к серверу | Каждый запрос подписан ключом участника. Сервер проверяет подписи, права, версию ключа и не даёт откатить данные |
| Удаление участника | Сервер сразу перестаёт его пускать. Ключи его коллекций меняются, записи перешифровываются |
| Вступление | Только по ссылке-приглашению (7 дней, до 25 человек), каждую заявку админ принимает вручную. В ссылке есть код команды, поэтому подменить команду нельзя |
| Браузер | Строгий CSP, никакого HTML из данных, ссылки только http/https, буфер обмена очищается через 30 с, автоблокировка |

Сервер (и Cloudflare) видит только зашифрованные данные, имена участников и время изменений. Названия коллекций тоже зашифрованы.

**Что важно знать:**
- Ссылка команды (`#t=…`) не даёт доступа к паролям без мастер-пароля, но не публикуйте её.
- Удалённый участник мог запомнить пароли, которые уже видел. Смените важные пароли на самих сайтах.
- Кто может менять код сайта (репозиторий на GitHub) или сервера (аккаунт Cloudflare), тот может украсть пароли. Не давайте никому эти доступы.
- Мастер-пароль не восстанавливается. Периодически делайте экспорт.

## Расширение для браузера (Chrome, Edge, Firefox)

Ищет записи, копирует логин, пароль и код 2FA, подставляет данные на сайт, генерирует пароли и предлагает сохранить новый пароль с сайта. Работает с тем же сервером и теми же ключами, что и приложение.

```sh
node extension/build.mjs      # соберёт extension/dist/chrome и extension/dist/firefox
```

- **Chrome / Edge / Яндекс Браузер:** `chrome://extensions` → «Режим разработчика» → «Загрузить распакованное» → папка `extension/dist/chrome`.
- **Firefox (115+):** `about:debugging#/runtime/this-firefox` → «Загрузить временное дополнение» → `extension/dist/firefox/manifest.json`. Временное дополнение пропадает после перезапуска браузера; для постоянной установки его нужно подписать на addons.mozilla.org (приватная подпись, публикация не нужна). Firefox может попросить разрешить доступ к адресу сервера: разрешите в `about:addons` → «Разрешения».
- Первый запуск: вставьте ссылку Ключницы (ту же, что даёт админ), выберите себя и введите мастер-пароль.
- Горячие клавиши: `Ctrl+Shift+K` открыть окно, `Ctrl+Shift+L` подставить логин и пароль для текущего сайта (меняются в настройках браузера).

Как защищено:
- Подстановка только по вашему действию и только на https (http — только localhost). Адрес записи должен совпасть с адресом страницы точно (www не в счёт), поддомены не подходят. Невидимые поля игнорируются, чужие фреймы не затрагиваются.
- Расшифрованные ключи лежат только в памяти браузера (`storage.session`), на диск не пишутся, скриптам страниц недоступны и стираются по таймеру автоблокировки и при запуске браузера.
- Пароль, пойманный на сайте, живёт в памяти 2 минуты и только пока Ключница разблокирована. Предложение сохранить показывается в окне расширения, а не на странице, поэтому сайт не может его подделать.
- Ответ входа на диск не кэшируется. Расширение просит только доступ к серверу Ключницы, к активной вкладке по клику и скрипт-перехватчик для ловли пароля на страницах.
- Не умеет: двухшаговый вход с логином на другом экране (логин при сохранении придётся ввести), очистку буфера обмена после закрытия окна (чистится только пока окно открыто).

Проверка: `node tests/ext.test.mjs` (правила адреса, подстановка, сборка манифестов).

## Новое в 2.2

- **Проверка паролей:** слабые, повторяющиеся, старые и утёкшие (по Have I Been Pwned, наружу уходят только 5 символов хеша).
- **Отправка секрета:** одноразовая ссылка на текст со сроком жизни и числом просмотров, шифруется на устройстве. Требует обновления сервера: `npx wrangler d1 execute <база> --remote --file=schema.sql`, затем `npx wrangler deploy`.
- **Сервер:** лимит попыток по паре «участник + IP», одинаковый ответ для несуществующего участника, окно подписи 120 с и защита от повтора, строгий CORS (для расширений можно задать `EXT_ORIGINS`).
- **PWA:** блокировка при пробуждении, очистка буфера при потере фокуса, кэш только для файлов приложения.

## Участник-сервис и CLI `kb` (для программ, например Директора)

Программа подключается к Ключнице как отдельный участник и работает без мастер-пароля: запросы подписываются её ключом, записи шифруются на её устройстве. Сервер по-прежнему видит только шифртекст.

- **Участник-сервис** - роль «участник» с флагом «сервис» (галочка в окне заявки). У него нет личного сейфа, отправок секрета и коллекций «для всех»; админом он стать не может, флаг не снимается (только удалить и принять заново). Видит только коллекции, куда его добавили явно. Это проверяют и приложения, и сервер.
- **CLI:** `node cli/kb.mjs help`. Ключи - только из переменных окружения (`KB_UID`, `KB_SIGN_SK`, `KB_BOX_SK`, `KB_TEAM_SECRET`, `KB_PIN`, `KB_API`), их подставляет хранилище ключей. Значения паролей CLI не печатает никогда: `kb run --item N --env VAR -- команда` кладёт пароль только в окружение дочернего процесса, `kb totp` - так же код 2FA. Дочернему процессу не передаётся ни одна переменная `KB_*` в любом регистре (на Windows `kb_sign_sk` и `KB_SIGN_SK` - одна переменная). Команда запускается без shell; на Windows `.cmd`/`.bat` (npm, npx) идут через `cmd.exe /d /s /v:off /c`, а аргументы со спецсимволами cmd (`" & | < > ^ % !`) для них отклоняются - такую программу запускайте напрямую (`node script.js`). Команды «показать пароль» нет.
- **Подключение:** владелец создаёт приглашение; на устройстве программы `node cli/kb.mjs enroll --link '<ссылка-приглашение>' --name Директор --out <файл>` (ключи - в файл, на экран - uid и код участника; файл создаётся пустым и закрывается до заявки: права 0600, на Windows - icacls только для текущего пользователя; не удалось закрыть - заявка не отправляется); владелец сверяет код, принимает заявку с галочкой «Участник-сервис», создаёт коллекцию (не «для всех») только с ним; ключи из файла переносятся в хранилище, файл удаляется; `kb selfcheck` должен ответить `ok`. На Linux/macOS файл создаётся с правами 600; на Windows права ставит `icacls` (только текущий пользователь, наследование снято), а если не вышло - `kb` пишет предупреждение: тогда перенесите ключи и удалите файл сразу.
- **Сервис и коллекции «для всех» не совмещаются.** Приложение до 2.3.0 и расширение до 2.3.0 требуют ключ коллекции «для всех» у каждого участника и сочли бы файл команды с сервисом подделанным. Поэтому и приложение, и сервер не дают принять сервис, пока в команде есть коллекции «для всех», и не дают создать такую коллекцию, пока сервис в команде (ошибка объясняет, что сделать). Перед подключением сделайте коллекции «для всех» (в новой команде это «Общие») «для выбранных» и отметьте нужных участников. Файл команды новее клиента (`v` > 1) клиент называет «обновите приложение», а не «подделан». Расширение собирается из тех же `js/vault.js` и `js/config.js`: `node extension/build.mjs` даёт версию 2.3.0 с правилами сервиса.

## Журнал запросов

Сервер пишет в таблицу `audit` строку только на запрос проверенного участника на известный путь: подпись запроса прошла, пароль при входе верный, заявка по приглашению принята (плюс удачное создание команды - от имени владельца). В строке: время, uid, метод, класс пути (`api/f/vault/*`), объект (id коллекции или участника), статус и HMAC адреса. Тела запросов, заголовки, параметры, id отправок и тексты ошибок в журнал не попадают.

- **Без строки** - всё остальное: запросы без секрета команды или с неверным, с верным секретом, но без подписи или с неверной подписью (секрет команды есть у всех, включая удалённых участников, - по нему одному строку не получить), неверный пароль, отклонённая заявка, неизвестный путь, открытие отправки по ссылке. Для них таблица `audit_denied` - счётчик на (день, класс пути, код ответа): поток мусорных запросов не раздувает базу и не вытесняет настоящие строки. Владельцу и админам он приходит в `GET api/audit` полем `denied`.
- **Квота и потолок - на участника:** не больше `AUDIT_UID_DAY` строк-чтений в сутки (по умолчанию 2000; сверх - одна строка `audit-quota`, дальше счётчик `quota:<uid>:<путь>`). Записи и удаления (всё, кроме GET и входа) квотой чтений не ограничены: у них свой потолок `AUDIT_UID_WRITE_DAY` (10000 в сутки; сверх - строка `audit-quota-write` и тот же счётчик). Не больше `AUDIT_UID_ROWS` строк всего (по умолчанию 20000; чистятся только его же старые строки, раз в 256 записанных строк). Владелец и админы в `GET api/audit` видят и `counts` - сколько запросов (чтений `n_day`, записей `w_day`) каждый участник сделал за сутки, включая сверхквотные. Поэтому ни участник, ни сервис не может вытеснить строки владельца, админов и других участников. Срок хранения - `AUDIT_DAYS` дней (по умолчанию 180), старое удаляется попутно. Счётчики квоты - таблица `audit_count` (строка на участника).
- **Сбой записи журнала** запрос не ломает, но и не теряется молча: считается в `audit_denied` как `audit-error:<путь>` (и имя ошибки - в лог воркера).
- **Адрес:** HMAC-SHA256 с секретом `AUDIT_SALT` из секретов Workers (`openssl rand -base64 32 | npx wrangler secret put AUDIT_SALT`). Без `AUDIT_SALT` адрес не пишется (`ip` - пустая строка): секрет из той же базы не годится - по дампу базы все IPv4 перебираются за минуты.
- `GET api/audit` отдаёт владельцу и админам весь журнал, участнику - только его строки (`kb audit`).
- **Миграция:** `schema.sql` - только `CREATE ... IF NOT EXISTS`, уже созданную таблицу `audit` он не меняет. Столбец `ip` - `TEXT NOT NULL DEFAULT ''`, сервер всегда пишет строку (HMAC или `''`), так что запись проходит и на таблице первой версии ветки (`ip TEXT NOT NULL`), и на промежуточной (`ip TEXT`); пересоздавать таблицу не нужно. Новые таблицы `audit_denied`, `audit_count` и `retired_uids` миграция добавит. Если `audit_count` уже была создана прежней версией ветки (без `w_day`), её надо пересоздать: `DROP TABLE audit_count;` и снова `schema.sql` (счётчики за сутки обнулятся).
- **uid не переиспользуется:** удалённый участник и отклонённая заявка попадают в `retired_uids`; заявка с таким uid отклоняется (409) даже с верным приглашением, приглашение не тратится. uid заявитель выбирает сам, поэтому без этого новый держатель приглашения получил бы строки журнала, квоту и счётчики прежнего участника.
- Обновление развёрнутого сервера: задать `AUDIT_SALT`, затем `npx wrangler d1 execute <база> --remote --file=schema.sql` и `npx wrangler deploy`. После деплоя в `GET api/audit` поле `denied` не должно копить `audit-error:*`: если копит - журнал не пишется (миграция не применена).

## Запуск с нуля

Сейчас всё уже развёрнуто. Этот раздел нужен, только если ставить заново.

```sh
cd server
npm i
npx wrangler login
npx wrangler d1 create keybox                 # id базы вписать в wrangler.toml
npx wrangler d1 execute keybox --remote --file=schema.sql
npx wrangler deploy                           # адрес сервера вписать в js/config.js и в CSP (index.html)
openssl rand -hex 16 | npx wrangler secret put SETUP_CODE
```

Потом откройте `https://<сайт>/#setup=<SETUP_CODE>` и создайте команду. Код одноразовый: после создания команды он больше ничего не даёт.

## Разработка

```sh
node tests/core.test.mjs     # ядро: шифрование, роли, подмены, откаты
node tests/server.test.mjs   # сервер: права, подписи, вход, приглашения, удаление
node tests/director.test.mjs # участник-сервис и журнал запросов
node tests/cli.test.mjs      # CLI kb: enroll, create, run, selfcheck; секреты не попадают в вывод и журнал
node tests/d1.test.mjs       # schema.sql и SQL хранилища на настоящем SQLite (Node 22.5+)
node tests/serve.mjs         # http://localhost:8765/#demo - демо без сервера, данные в памяти
cd server && npx wrangler dev --local   # локальный сервер
```

Сборки нет, это чистый JS (ES-модули). Сервер использует те же модули `js/crypto.js` и `js/vault.js`, поэтому правила у клиента и сервера одинаковые. Единственная внешняя библиотека — `vendor/argon2.umd.min.js` (hash-wasm 4.12.0, MIT), подключена с SRI: `sha384-tP0Wy54CKmng7i9EoTlPySD0hBx6Octj0VS6MfwlnUu111MPa+JLm0CCbep6XJ1W`.

После изменения файлов приложения поднимите `CACHE` в `sw.js`, чтобы у пользователей обновился офлайн-кэш.
